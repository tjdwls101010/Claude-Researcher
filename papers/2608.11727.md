# 🖇️Harness-IF: 코딩 에이전트가 읽는 여러 지시 표면에서 지시 준수를 평가하기

## 🎯 에이전트가 규칙을 지킨 건지, 원래 그렇게 하려던 건지

코딩 에이전트가 규칙 하나를 지켰을 때, 사실은 그 규칙이 없어도 똑같이 했을 수 있다. 기존 벤치마크는 이 둘을 구분하지 못한다. 지시 준수(instruction-following, IF) 벤치마크는 규칙을 사용자 턴에 몰아넣고, 코딩 에이전트 벤치마크는 최종 과제 성공률을 강조한다. 어느 쪽도 긴 harness 워크플로 도중에 에이전트가 **어떤 운영 규칙을 실제로 따랐는지**를 직접 드러내지 않는다.

배포된 코딩 에이전트는 저장소를 살피고, 파일을 고치고, 명령을 실행하고, 도구를 호출하고, 여러 턴에 걸쳐 응답하는 동안 지시가 층층이 쌓인 스택 아래에서 동작한다. 따라서 준수는 응답 하나를 넘어, 그리고 시스템 프롬프트·도구 및 스킬 설명·`CLAUDE.md` 같은 프로젝트 파일·사용자 지시에 걸쳐 지속되어야 한다.

이 논문은 **지시 표면(instruction surface)**과 **지시 위계(instruction hierarchy)**를 구분한다. 위계는 충돌 상황에서 어느 권한 있는 출처가 이겨야 하는가의 문제다(Wallace et al. (2024)). Harness-IF는 그 대신 **운영상의 전달 표면 자체**를 평가 차원으로 바꾼다. 규칙의 의미는 고정한 채 전달 위치만 옮기는 통제된 재배치(controlled relocation) 설계라, 표면끼리 짝지어 비교할 수 있다. 논문은 이 설계를 통제된 충돌 파일럿(E0)에서 쓰고, 규칙을 운영상 허용 가능한 표면에 배정하는 더 큰 코딩 패널로 보완한다. 통제된 식별과 넓고 현실적인 커버리지를 함께 얻으려는 조합이다.

기여는 세 가지다. 첫째, **과제가 아니라 규칙을 채점하는 벤치마크**다. 642개 규칙 라이브러리 중 302개를 배포된 코딩 에이전트의 다섯 개 설정 가능 지시 표면 위에 올려 60개의 현실적인 멀티턴 아이템으로 만들었고, 그중 256개가 실행에 근거한 판정을 받는다. 판정은 런당 적용 가능한 규칙 하나에 하나씩 나온다. 둘째, **프롬프트 없이 나오는 기본 행동을 통제하는 지표**다. AP-Acc는 기본 동작에 반한다고 라벨된 규칙만 채점하며, 라벨은 증거를 복구할 수 있는 경우 zero-injection 프로브에서 관찰하고 그 밖에는 큐레이션으로 붙였다. 셋째, **증거**다. 12개 모델 전부가 like-for-like 및 공통 지지(common-support) 분석 모두에서 against-prior 규칙에 더 취약하고, 규칙 계열과 양상(modality)마다 난이도와 실패 서명이 뚜렷이 다르며, E0는 단순한 프롬프트 깊이 설명과 맞지 않는 견고한 통합 표면 순서를 드러낸다.

평가는 상호 보완적인 세 부분으로 이뤄진다. 메인 코딩 패널이 12개 모델에서 규칙 단위 준수와 prior 정렬을 재고, E0가 네 개의 균형 배치된 충돌과 아홉 개 모델 빌드로 표면 우선순위를 분리하며, 비코딩 확장이 도메인에 맞는 case-macro 지표로 40개 케이스에서 폭을 시험한다.

## 🧭 다섯 개의 설정 가능 표면과 하나의 고정 표면

현대 코딩 에이전트의 일반적인 구성을 따라 여섯 개의 지시 표면을 구분한다.

**Harness Default(HD)**는 에이전트 플랫폼이 각 런 시작에 삽입하는 기본 지시로, 배포 환경에서 사용자가 보통 편집할 수 없다. **System Prompt(SP)**는 시스템 개발자가 에이전트의 역할과 일반 행동을 정하려고 쓴 지시로, "절대 비밀을 노출하지 마라"나 "높은 확신으로 답하라" 같은 것이다. **Tool Description(TD)**은 도구가 무엇을 하고 에이전트가 그것을 어떻게 써야 하는지를 서술한다. **Skill Description(SD)**은 재사용 가능한 스킬을 언제 써야 하고 쓸 때 어떤 규칙을 따라야 하는지를 서술한다. **Project File(PF)**은 `CLAUDE.md`, `CONTRIBUTING.md`, `AGENTS.md` 같은 파일에 저장된 프로젝트 수준 지시다. **User Instruction(UI)**은 사용자가 지금 에이전트에게 하는 요청이다.

이 표면들은 플랫폼 개발자, 도구 작성자, 프로젝트 관리자, 사용자처럼 서로 다른 주체가 쓰고, 프롬프트의 서로 다른 위치에 나타난다. 형식적으로는 제약 하나를 $x$, 에이전트 출력을 $y$, 제약이 놓인 표면을 $s$라 하고, 표면 $s$로 전달된 제약 $x$를 출력 $y$가 만족하는지 판정하는 규칙 단위 평가자를 $F(x, y, s) \in \{\text{pass}, \text{fail}, \text{n/a}\}$로 쓴다. 대부분의 벤치마크는 $s$를 사용자 지시에 고정해 둔다. Harness-IF는 다섯 개의 설정 가능 표면 $s \in \{\text{SP}, \text{TD}, \text{SD}, \text{PF}, \text{UI}\}$에 놓인 제약을 얼마나 잘 따르는지를 평가한다.

Table 1은 대표적인 최근 벤치마크와의 비교다. Surfaces는 그 벤치마크가 대표하는 서로 다른 지시 전달 표면의 수인데, Harness-IF는 여섯(HD, SP, TD, SD, PF, UI)이고 그중 HD는 고정, 나머지 다섯이 설정 가능한 배치 표면이다. 배치는 E0 충돌 파일럿에서는 실험 변수로 변화시키고, 메인 패널에서는 허용 가능성(admissibility)에 따라 배정한다. Prior Control은 프롬프트 없는 기본 행동을 명시적으로 통제하는지를 뜻한다. 원표에서는 ✓가 완전 지원, •가 부분 지원, –가 부재를 뜻한다.

관련 연구 위치는 이렇게 잡힌다. IFEval(Zhou et al. (2023))이 검증 가능한 제약을 표준 프로토콜로 만들었고, FollowBench, InfoBench, ComplexBench가 난이도 등급·정보 제약·다중 제약 합성으로 공간을 넓혔다. 최근 벤치마크들은 프롬프트를 더 많이 넣기보다 더 어렵게 만든다. Multi-IF는 다국어 멀티턴 대화를 더하고, CFBench·LIFBench·EIFBench는 복잡하거나 긴 컨텍스트의 제약 집합을 압박하며, IFBench는 검증 가능한 규칙 검사를 넓히고, AgentIF는 에이전트적 IF 시나리오를 도입한다. 이들은 제약 단위 측정을 확립했지만 실험 변수는 여전히 주로 지시 내용이나 시나리오다. Harness-IF는 다른 질문을 한다 — **같은 규칙이 다른 harness 표면으로 전달돼도 에이전트가 여전히 따르는가**.

에이전트·코딩 평가 쪽에서는 AgentBench와 GAIA가 범용 어시스턴트를, WebArena·OSWorld·BFCL·AppWorld·τ-bench·τ²-bench가 웹·데스크톱·도구 호출·애플리케이션·사용자 상호작용 에이전트를 평가한다. 기술 작업 쪽으로는 SWE-bench 계열, Terminal-Bench, MLAgentBench/MLE-bench/PaperBench 라인이 있다. 충실도는 높지만 대표 점수는 대개 궤적 하나를 과제 성공 여부로 접어 버린다. Harness-IF는 현실적인 코딩 에이전트 실행을 쓰되 지시 준수 자체를 측정 대상으로 삼는다는 점에서 상보적이다.

harness와 궤적 평가 쪽으로는, 배포된 에이전트에서 모델은 시스템의 한 부분일 뿐이고 행동은 시스템 프롬프트·도구 스키마·스킬·프로젝트 파일·메모리·재시도, 그리고 평가자에게 보이는 궤적이 함께 만든다는 관점이 있다. Toolformer와 Gorilla는 도구 컨텍스트가 왜 중요한지 보이고, 지시 위계 연구와 IHEval(시스템·사용자·이력·도구 출력 메시지에 걸친 합성 충돌)은 권한 컨텍스트가 왜 중요한지 보인다. IHEval은 규정된 메시지 위계에 대한 준수를 시험하는 반면, Harness-IF는 실행 가능한 작업 공간에 분산된 제약을 측정하고, E0는 보편적 순서를 가정하지 않은 채 더 넓은 표면 집합에서 우선순위를 추정한다. 최근 논문들도 같은 지점을 다른 각도에서 말한다. MCP 도구 설명이 에이전트 효율에 영향을 주고(Hasan et al. (2026)), 열린 스킬 매니페스트는 감사가 필요하며(Ying et al. (2026)), 과정상의 결함은 최종 과제 평가를 통과해 살아남을 수 있고(He et al. (2026)), 장기 코딩 에이전트는 벤치마크 명세를 악용할 수 있다(Zhao et al. (2026)).

## 🧱 642개 원자 제약, 60개 아이템, 256개 판정

**제약(constraint)**은 에이전트가 따르도록 요구받는 하나의 구체적 규칙이고, 런의 실행 증거로부터 pass·fail·not applicable을 판정할 수 있을 만큼 좁다. 계열은 일곱이다 — professional writing, output control, code style, workflow, quantitative limits, conditional logic, tool use.

**표면 배정**은 허용 가능성으로 정한다. 배포 상황에서 그 표면의 작성 주체가 그 규칙을 담을 법할 때 그 표면에 허용된다. 브랜치 이름 규칙은 프로젝트 파일이나 시스템 프롬프트에 놓일 수 있지만 도구 스키마에는 놓일 수 없다. 여러 표면이 허용되면 균등하게 하나를 뽑고, 규칙 의미를 보존하는 표면별 표현을 쓴다. 이 설계는 메인 패널에서의 서술적 표면 층화를 뒷받침하며, 통제된 충돌 비교는 E0가 담당한다.

**시나리오**는 백엔드 API 버그 수정, 프론트엔드 컴포넌트 업데이트, 데이터 처리 스크립트 편집, 테스트 작성, 프로젝트 문서 변경 같은 현실적 코딩 과제의 작업 파일을 제공한다. 그래서 아이템마다 언어, 파일 배치, 요구되는 편집 종류가 다르다. 평가 패널은 13개 시나리오 라이브러리 중 여덟 개를 쓰며, 백엔드·프론트엔드·시스템·데이터/ML·자동화·보안 테스트·도구 오케스트레이션·기술 문서를 아우른다.

Figure 3은 642-규칙 라이브러리의 구성을 세 개의 독립 주석 축으로 보여준다. 계열별로 writing 28%, output 18%, code style 18%, workflow 11%, tool use 9%, conditional 9%, quantitative 8%다. 논리적 양상별로는 require 60%, forbid 13%, conditional require 10%, limit-max 7%, prefer 6%, limit-min 3%, allow 1% 미만이다. prior 라벨은 align 18%, against 44%, neutral 38%다. 이 그림은 라이브러리를 서술하는 것이지 평가된 부분집합이 아니다 — 코딩 패널은 이 중 302개를 인스턴스화하고 256개를 채점하며, professional-writing 규칙은 비코딩 확장에서만 사용된다. prior 라벨을 의도적으로 섞은 이유는 기본 행동만으로는 패널을 통과할 수 없게 하기 위해서다. 시나리오는 별도의 주석 축이라 이 그림에 집계되지 않는다.

데이터 큐레이션은 네 단계다. **원천 수집**은 공개 접근 가능한 GitHub 소프트웨어 프로젝트를 수작업 조사하는 데서 시작했고, `CLAUDE.md`, `AGENTS.md`, `CONTRIBUTING.md`, 스킬 설명, 도구 스키마 같은 프로젝트 지시·기여자 문서를 여러 프로그래밍 언어와 소프트웨어 엔지니어링 워크플로에 걸쳐 봤다. 반복되는 요구사항을 벤치마크용 규칙으로 원자화하고 표면별 표현에 맞춰 정규화했으며, 검토를 거친 LLM 제안과 저자 검토로 커버리지가 부족한 분류 셀을 채웠다. 결과 과제·명세·채점 산출물은 원천 저장소를 그대로 복사한 것이 아니라 프로젝트가 직접 작성한 것이다. 상세 출처는 내부 감사와 권리 검토용으로 유지하되 공개 산출물에는 거친 출처 범주만 노출해, 개별 제약을 특정 저장소에 직접 연결할 수 없게 했다. 코딩 작업 공간은 현실적인 기술 스택에 맞춰 조립했고 2026-07-27 소유자 확인서에 따라 릴리스에 포함된다.

**필터링과 아이템 포매팅**에서 후보 제약은 원자적·검증 가능·비자명해야 하고 코딩 에이전트 과제에 적합해야 한다. 제안은 중복 제거와 사람 검토를 거쳐 채택되며, 커버리지가 부족한 범주는 표적 확장한다. 시나리오와 작업 파일 세트마다 제약을 골라 각각을 허용 가능한 표면 하나에 배치한다.

**품질 필터링**에서는 80개 후보 중 60개 아이템이 남았다. 선정에 관찰된 난이도와 변별력을 썼기 때문에, 보고된 패널은 파일럿 모델들을 갈라놓은 아이템 쪽으로 치우쳤을 수 있다(선택 낙관, selection optimism). Datasheet 기준으로 80개 후보 중 60개 유지, 15개 폐기, 5개 제외이며, 일부 아이템별 승격·검토 산출물은 복구되지 않는다.

총계로 라이브러리는 642개의 원자 제약을 담고 평가 패널은 60개 멀티턴 아이템으로 구성된다. 각 아이템은 25–35개 규칙 팩을 주입하며, 그중 10–27개가 아이템이 만들어내는 기회를 볼 때 채점 가능하다. 패널 전체로는 302개의 서로 다른 라이브러리 규칙이 인스턴스화되고 256개가 최소 한 번의 판정을 받는다.

### 🏷️ 여덟 개 주석 축

라이브러리의 642개 원자 제약은 각각 여덟 개의 분리 가능한 축으로 태깅된다.

**Family(7)**은 professional-writing, output-control, code-style, workflow, quantitative, conditional-logic, tool-use이고 시나리오 적용 가능성과 독립이다. 합성 예시로는 구현 후 검증 단계를 요구하는 규칙(workflow), 자유 형식 대신 구조화된 도구 파라미터를 요구하는 규칙(tool-use)이 있다.

**Modality(7)**은 논리 연산자로 require, forbid, conditional-require, limit-max, limit-min, prefer, allow다. 같은 내용에 대한 forbid와 require는 서로 다른 지시이므로, 양상은 계열만으로는 놓치는 난이도 구조를 잡는다. 합성 예시로 짧은 완료 요약 요구, 생성된 캐시 파일 금지, 설정이 바뀔 때 검증 요구, 간결한 리포트 형식 선호가 있다.

**Prior(3)**는 지시가 없을 때 모델이 관찰상 또는 큐레이션상 보이는 기본 행동으로 align-prior(지시가 기본 성향과 맞음), against-prior(지시가 기본 성향을 거스름), neutral이다. zero-injection ablation은 대상 규칙을 뺀 채 아홉 개 프로브 빌드에서 각 과제를 다시 돌리고, 아홉 중 최소 다섯이 일치하면 합의 라벨을 준다. 이 합의는 287개 규칙에 대해 복구 가능하다. 나머지 최종 라벨은 복구 가능한 기존 큐레이션 값을 쓰거나 계보가 불명이다. 이 프로브 코호트는 E0 충돌 파일럿에 쓰인 것과 같은 아홉 빌드지만 거기서는 다른 과제로 다른 목적을 위해 돌렸고, 두 실험은 별개이며 결과는 결코 통합되지 않는다. 아홉 중 다섯은 평가 패널의 모델과 식별자를 공유한다. 현재 관리되는 총계는 align-prior 115, against-prior 282, neutral 245다. 이 라벨은 행동 계층이지 학습 출처에 대한 인과 주장이 아니다.

**Observability(4)**는 준수가 어디서 보이는지로 surface(마지막 턴의 토큰), structural(파일 배치, AST), behavioral(테스트 통과·부작용), deep(의미적 의도)이다. **Verifiability(3)**는 준수를 어떻게 검사할 수 있는지로 deterministic(정규식, AST 매치, 파일 간 동등성), rubric(작성된 루브릭에 대한 LLM 판정), subjective(사람만 가능, 현재 채점에 미사용)다. **Universality(4)**는 적용 범위로 universal, cross-coding, cross-non-coding, specific이다.

**Surface fit**은 제약마다 표면별 적합도 점수 {none, low, medium, high}를 붙여 의미상 불가능한 배치를 막는다. **Surface variants**는 허용되는 표면마다 의미를 보존하면서 그 표면의 역할에 맞는 사전 작성 표현을 갖는다. 예컨대 간결한 요약 규칙이면 SP는 "Keep generated summaries compact", PF는 "Output style: compact summaries", UI는 "Return a compact completion summary"로 쓸 수 있다.

(family × modality × prior × observability × verifiability × universality) 조합 공간은 $7 \times 7 \times 3 \times 4 \times 3 \times 4 = 7056$개 셀이다. 642개 제약은 수사적 내용 기준 중복 제거 후 그중 약 420개 셀을 채우고, 나머지는 의미상 비어 있거나(예: forbid × subjective) 현재 라이브러리에서 과소 채워져 있다. 해시로 고정된 이력 산출물이 공개 프로젝트 지시·기여자 문서가 최초 작성 물결에 반영됐음을 확인해 주고, 이후 커밋은 사람이 승격한 13개 시드 레코드를 보존하지만 현재 규칙으로의 매핑은 확립되지 않았다. 따라서 라이브러리는 저장소 인구조사가 아니라 경험적으로 근거 지어진 벤치마크 콘텐츠로 읽어야 한다.

## 📐 Acc, F-Acc, DW-Acc, 그리고 AP-Acc

에이전트 출력마다 평가자가 각 제약을 passed·failed·not applicable로 판정한다. 에이전트 $a$가 아이템 $i$에서 제약 $r$을 만족하면 $z_{a,i,r} = 1$, 아니면 $0$이다. $E_a$는 에이전트 $a$에 대한 pass/fail 제약 인스턴스 집합이다. not-applicable 제약은 분모에서 빠지는데, 그 아이템이 해당 규칙을 따랐는지 판정할 유효한 기회를 만들어 주지 않기 때문이다.

like-for-like 이진 재계산에서 기본 정확도는 모든 적격 제약 인스턴스를 동등하게 다룬다.

$$\text{Acc}(a) = \frac{\sum_{(i,r) \in E_a} z_{a,i,r}}{|E_a|} \quad (1)$$

코호트 적응형 진단 지표 둘도 함께 보고한다. 첫째, **필터링 정확도(F-Acc)**는 평가 코호트 안에서 에이전트를 구분하지 못하는 아이템–규칙 쌍을 제거한다. $D$를 에이전트들 사이에서 서로 다른 pass/fail 결과를 내는 아이템–규칙 쌍의 집합이라 하자.

$$\text{F-Acc}(a) = \frac{\sum_{(i,r) \in E_a \cap D} z_{a,i,r}}{|E_a \cap D|} \quad (2)$$

둘째, **변별력 가중 정확도(DW-Acc)**는 평가 에이전트들을 더 잘 갈라놓는 규칙에 더 큰 가중치를 준다. $d_r \geq 0$은 규칙 $r$에 대한 에이전트들의 통과율과 전체 정확도 사이의 비음 피어슨 상관이며, 변별력이 0 이하이거나 정의되지 않는 규칙은 $d_r = 0$을 받는다.

$$\text{DW-Acc}(a) = \frac{\sum_{(i,r) \in E_a} d_r z_{a,i,r}}{\sum_{(i,r) \in E_a} d_r} \quad (3)$$

규칙이 기본 행동과 일치할 때 정확도와 AP-Acc는 달라질 수 있다. 그래서 zero-injection 증거와 큐레이션된 prior 주석으로 행동적 prior 라벨을 부여한다. AP-Acc는 학습 출처에 대한 주장이 아니라 행동적 층화다.

**against-prior 정확도(AP-Acc)**는 against-prior 집합 $P$에 속한 제약만 평가한다. 대응하는 기본 행동에 반한다고 라벨된 제약에서의 성능을 보고하는 지표다.

$$\text{AP-Acc}(a) = \frac{\sum_{(i,r) \in E_a,\, r \in P} z_{a,i,r}}{|\{(i,r) \in E_a : r \in P\}|} \quad (4)$$

네 개의 표시 열은 모두 릴리스된 2,160-레코드 패널에서 위 식으로, 같은 적격 판정 집합 위에서 계산된다. 그래서 $\Delta$는 집계 관행의 차이가 아니라 like-for-like 대비다. F-Acc와 DW-Acc는 코호트 상대적 진단이라 서술적으로만 해석하며, 평가 코호트가 바뀌면 둘 다 바뀐다.

### ⚙️ 채점 방법과 캐스케이드 처리

아이템 안의 각 규칙은 작성 시점에 그 제약을 무엇에 비춰 검사할 수 있는지에 따라 여섯 방법 중 하나로 채점된다. **regex**는 마지막 턴 메시지나 특정 파일에 대한 표면 패턴 매치, **ast**는 생성 코드의 AST 구조 매치(함수 존재, 데코레이터 사용, import 순서 등), **cross-file**은 생성된 작업 공간 전체의 파일 간 일관성 검사, **command-output**은 제공된 컴파일 또는 테스트 스크립트를 실행해 종료 코드/stdout을 채점, **hybrid**는 결정론적 사전 검사(후보를 좁힘) 뒤 LLM 정제(모호성 해소), **LLM-judge**는 전체 런을 읽는 LLM 판정자의 루브릭 기반 채점이다. LLM-judge와 hybrid는 temperature 0.3에서 세 번 독립 평가한 뒤 다수결을 쓴다. 고정된 코딩 평가의 판정자는 GPT-5.2다.

모든 규칙 인스턴스는 must, should, may 중 하나의 심각도를 갖고, 릴리스 레코드는 가중치 없는 상태와 심각도 가중(각각 3, 2, 1) earned/possible 합계를 둘 다 보존한다. 이 논문이 보고하는 모든 지표는 가중치 없는 이진 비율이므로 심각도는 표시된 어떤 수치에도 영향을 주지 않고, 가중 관점을 원하는 다운스트림 사용자와 아이템 작성 시의 아이템별 MUST 게이트를 위해 유지된다.

고정 패널은 40,104개의 method 행을 담고 그 내역은 pass 29,176, fail 8,440, no-opportunity 2,320, partial 168이다. like-for-like 이진 재계산은 37,616개의 pass/fail 판정을 남기고, AP-Acc는 최종 규칙 라벨이 against-prior인 19,449개의 적격 판정을 쓴다. 이 수치들은 12모델·60아이템·3라운드 코딩 패널에만 적용되며, 비코딩·E0·온라인 패널은 별개의 모집단과 지표를 쓴다.

**캐스케이드 중복 제거**: 산출물 하나가 빠지면 그것에 의존하는 여러 규칙이 동시에 실패할 수 있다. dedup-cascade 패스는 가장 심각도가 높은 실패 하나만 남기고 나머지 의존 결과를 no-opportunity로 바꿔, 산출물 하나의 부재가 실패를 증식시키지 못하게 한다. **캐스케이드 공정성 감사**: 배치가 끝난 뒤 audit-cascade-fairness는 에이전트의 50% 이상이 그 규칙을 검사하는 데 필요한 산출물을 만들지 못한 규칙을 untestable-design-gap으로 승격한다. 그런 규칙은 분모에서 제외되며, 감사에는 최소 5개의 테스트된 에이전트가 필요하다.

모델들은 어떤 규칙이 어려운지에 대해 대체로 의견이 일치한다. 모든 모델이 시도한 242개 규칙에서 각 모델의 규칙별 통과율 벡터를 코호트 평균과 상관 지으면 0.57–0.89(평균 0.80)이 나온다. 따라서 패널은 공유된 난이도 순서를 재고 있고, 그래서 인접 순위 교환이 잡음이 아니라 정보가 된다. 더 엄격한 빌드 대 빌드 쌍별 상관은 0.32–0.83(평균 0.62)이라, 리더보드는 대체로 공유된 난이도 구조를 반영하되 개별 규칙에서는 빌드마다 실제 개성이 있다.

**against-prior 규칙은 일관된 준수 격차를 드러낸다.** like-for-like 이진 정의 아래, 37,616개 적격 판정에서 Acc–AP-Acc 평균 격차는 5.81포인트이고 12개 모델 모두에서 양수로 남는다. 더 엄격한 공통 지지 분석은 3,342개의 (아이템, 라운드, 규칙) 관측 키 중 모든 모델이 깨끗한 pass/fail 결과를 낸 2,430개(72.7%)를 남기며, 이 위에서 짝지은 격차의 아이템 클러스터 95% 구간은 모델별로 여전히 양수다. 이 고정된 패널 위에서 방향은 안정적이다 — 12개 빌드 전부에서, 총계 지시 준수 점수가 관찰된 기본값에 반하는 규칙에서의 성능을 웃돈다.

**벤치마크는 인접 순위보다 넓은 패턴을 더 분명히 해상한다.** 공통 지지 위에서 아이템 클러스터 구간은 모든 인접 모델 비교를 미해결로 남기므로, 논문은 표시된 순서를 점 추정 랭킹으로 다루고 주장은 prior 정렬과 실패 패턴 결과에 얹는다.

## 🕳️ 실패는 행동을 요구하는 규칙에 몰린다

실패를 위반된 규칙이 무엇을 요구하는지로 묶는데, 이 분류는 자유 텍스트 분류 없이 릴리스된 레코드에서 복원할 수 있다. 행동을 요구하거나 최솟값을 정하는 규칙은 에이전트가 미달함으로써만 실패할 수 있고, 행동을 금지하거나 수량에 상한을 두는 규칙은 에이전트가 넘어섬으로써만 실패할 수 있다. 라이브러리의 모든 규칙이 논리적 양상을 갖고 있으므로, 각 실패는 판정자의 이유 문자열을 들여다보지 않고 규칙 정의만으로 클래스에 배정된다. 튜닝된 키워드도, 모델별 조정도, 잔여 버킷도 없다.

| Class | Failures | Share | Fail rate |
|---|---|---|---|
| Shortfall | 6,507 | 77.1% | 23.8% |
| Overstep | 1,758 | 20.8% | 20.8% |
| Preference | 175 | 2.1% | 9.4% |
| Total | 8,440 | 100.0% | 22.4% |

shortfall 규칙이 8,440개 실패 중 77.1%를 흡수하고, overstep 규칙이 20.8%, 소프트 선호가 2.1%다. 이 비대칭은 성향이 아니라 **노출**을 반영한다. 패널은 shortfall 인스턴스 27,306개에 overstep 인스턴스 8,443개를 담고 있고, 두 클래스는 비슷한 비율로 실패한다(23.8% 대 20.8%). shortfall 규칙은 overstep 규칙의 3.7배 실패 질량을 지지만, 그건 대체로 운영 규칙 집합이 무엇을 요구하는지의 속성 — 주로 행동을 요구한다는 것 — 이지 에이전트가 과잉보다 누락에 뚜렷이 취약하다는 증거가 아니다. 소프트 선호만이 진짜로 더 쉬운 클래스로 9.4%에서 실패한다. 현실적인 코딩 작업에서 준수 실패의 대부분은 요구된 행동의 누락이므로, 과잉 출력 탐지에 맞춰진 검증기는 실패 질량의 약 5분의 1만 다루는 셈이다.

계열별로도 실패 질량이 고르지 않다. output control과 workflow가 합쳐 전체 실패의 53.9%(27.6%와 26.3%)를 차지하고, 그 뒤로 code style 15.7%, conditional logic 12.4%, tool use 9.5%, quantitative limits 8.6%다. output control은 가장 큰 실패 질량과 가장 낮은 통과율을 함께 갖고 있어 개선 대상으로 가장 생산적이다. workflow의 질량은 대신 패널에서의 크기에서 나오는데, 통과율은 중간대이기 때문이다.

초기 원고들은 판정자 이유 문자열에 키워드 분류기를 돌려 만든 12버킷 분류를 보고했고 거기에는 19.2%의 미분류 잔여 버킷이 있었다. 그 분류는 버킷 비율을 릴리스된 산출물에서 재생성할 수 없었고, 이유 문자열이 다국어 자유 텍스트인 데다 부정 단서가 거의 모든 실패에 나타나 키워드 배정이 신뢰할 수 없었기 때문에 폐기됐다. 위 분해는 더 거칠지만 모든 수치를 독자가 배포된 레코드에서 재계산할 수 있다.

## 🧪 명령형 규칙과 output control이 가장 어렵다

난이도는 논리적 양상과 규칙 계열 양쪽에서 상당히 다르다. 난이도 보고를 위해 관리되는 일곱 개 양상 연산자를 네 개의 거친 클래스로 묶는다 — Commanding(require/forbid), Conditional(conditional-require), Quantitative(limit-max/limit-min), Preference(prefer/allow). 이 거친 "Quantitative" 클래스는 묶인 양상이고 같은 이름의 규칙 계열과는 별개다. 릴리스된 코딩 스코어카드는 일곱 라이브러리 계열 중 여섯 개의 계열 집계를 제공하며, professional writing은 이 비교에 포함되지 않는다.

양상별로 Commanding 76.0%, Numeric bounds 79.4%, Conditional 79.7%, Preference 90.6%다. 명령형 규칙이 가장 어렵다. 선호 결과는 기본값 정렬과 부합한다 — 선호는 기존 행동과 맞을 수 있는 반면 명령은 종종 거기서 벗어나기를 요구한다. Figure 5는 12개 빌드를 통합한 이진 정확도를 양상별(위)과 판정을 받는 여섯 계열별(아래)로 보여주며, 각 패널에서 가장 낮은 막대를 강조한다.

계열 차이는 더 좁다. output control이 70.9%로 quantitative limits의 82.6%에 맞서 11.7포인트 폭을 만든다. output control은 12개 빌드 중 11개에서 가장 낮은 점수 계열이고, 어떤 빌드도 이 계열에서 79%를 넘지 못한다.

## 🪜 표면 우선순위는 프롬프트 깊이를 따르지 않는다

E0는 표면 우선순위에 대한 통제되고 범위가 한정된 시험이다. 시스템 프롬프트, 프로젝트 파일, 사용자 지시가 최고 평균 순위를 정확히 공유한다 — 각각 모델 수준 순위 합이 20이라 $20/9 = 2.22\ldots$다. 이들이 도구 설명 3.78과 스킬 설명 4.56을 앞선다. 여기서 프롬프트 깊이란 조립된 컨텍스트 안의 위치를 뜻하고 사용자 턴이 마지막인데, 깊이 설명은 나중에 놓인 지시가 이긴다고 예측한다. 사용자 지시가 1위를 공유하기만 한다는 사실은 그런 설명과 맞지 않는다.

E0는 아홉 개의 더 오래된 모델 빌드가 네 개의 합성 충돌 쌍에서 만든 916개 런을 담고, 결정론적 채점만 쓰며, 메인 코딩 패널과 통합되지 않는다. 균형 배치는 각 방향에 458개 런을 할당하고 889개가 결정적 결과를 낸다. 통합 Bradley–Terry 분석은 SP, PF, UI를 TD 위에 놓고 SD를 마지막에 둔다. 이 순서는 방향별 개별 적합, 셀 균등 가중, 모든 leave-one-pair/model-out 적합, 그리고 27개 오류에 대한 네 가지 보수적 배정에서 살아남는다. 모델과 쌍을 교차한 부트스트랩은 10,000회 재표집 중 9,652회에서 완전한 순서를 보존하지만, 개별 빌드 적합은 9개 중 6개만 정확히 재현하므로 논문은 이를 보편적 위계가 아니라 통합된 빌드 간 경향으로 해석한다. 메인 패널은 대신 적합한 규칙을 표면에 배정해 짝지은 표면 효과가 아니라 서술적 층화를 뒷받침한다.

E0의 세부는 이렇다. 2026-04-25에 수집됐고, 아홉 빌드는 Claude Opus 4.6, Claude Sonnet 4.6, GPT 5.4, Gemini 3.1 Pro, DeepSeek V3.2, Kimi K2.5, MiniMax M2.7, Qwen 3.6 Plus, Seed 2 Pro다. 그중 넷은 메인 코딩 패널에 없고, 이것이 E0를 메인 패널과 통합하지 않는 한 이유다. E0는 현재 표면 명명법보다 앞서므로 두 개의 레거시 채널 라벨을 표준 집합에 CM→프로젝트 파일(PF), SK→스킬 설명(SD)으로 매핑해 보고한다. 순위는 각 모델의 맞대결 승수에서 다시 계산하고, 집중 재실행 횟수가 고르지 않음에도 모델 간 동등 가중으로 평균 낸다.

E0는 짝지은 결과가 아니라 균형 배치를 쓴다. 각 AB 런과 BA 런은 별개의 새 세션이고, 한 규칙 쌍의 상호 배타적인 구성원들이 같은 고정 과제에 대해 반대 표면에 배정된다. 설계는 방향당 458개 런을 담고, 27개 오류 뒤 AB 445개와 BA 444개가 결정적이다. 이 889개 결과에서 통합 Bradley–Terry 적합은 합이 0이 되는 로그 강도로 SP = +0.57, PF = +0.65, UI = +0.60, TD = −0.53, SD = −1.29를 준다. 모델과 충돌 쌍이 교차 요인이므로 주 불확실성 분석은 36개 모델–쌍 셀을 독립 클러스터로 다루는 대신 아홉 모델과 네 쌍을 독립적으로 재표집한다(고정 시드 10,000회 반복). 완전한 SP/PF/UI > TD > SD 순서는 교차 부트스트랩 재표집 9,652/10,000에서 나타난다(상위 그룹이 TD 위: 98.81%, TD가 SD 위: 97.71%). 이 값들은 재표집 방식에 조건부인 몬테카를로 진단이지 $p$-값이 아니다. 선두 세 표면은 가용한 정밀도에서 통계적으로 구분되지 않는다.

통합 순서는 방향별 적합(445/444개의 결정적 행), 네 개의 leave-one-pair-out 적합 전부, 아홉 개의 leave-one-model-out 적합 전부, 그리고 694개 모델×쌍×방향×표면 대결 셀의 균등 가중(반복 범위 1–5)에서도 살아남는다. 모든 오류를 결정론적으로 배정하는 네 방식 — 채널 A 승, 채널 B 승, 기대가 높은 그룹 승, 기대가 낮은 그룹 승 — 에서도 살아남는다. 오류는 DeepSeek V3.2(14개)와 Seed 2 Pro(10개)에 몰려 있어서, 결과와 무관한 삭제를 가정하기보다 이런 명시적 경계를 두는 편이 낫다. 이질성은 여전히 실질적이다 — 네 개의 쌍 단위 적합은 전부 정확한 순서를 재현하지만 아홉 개의 모델 단위 적합 중 여섯 개만 재현한다. AB가 유지된 수집에서 BA보다 먼저 실행됐고, 균형 배치는 규칙 정체성 문제를 다루지만 고정된 시간 순서는 사후에 교정할 수 없다.

E0의 SD 순위와 메인 패널의 SD 정확도는 서로 다른 방향을 가리키지만 논문은 이를 충돌로 보지 않는다. E0는 두 표면이 반대되는 것을 요구할 때 어느 표면이 이기는지를 묻고 SD를 마지막에 놓는 반면, 메인 패널은 규칙이 유일한 지시일 때 얼마나 자주 따르는지를 묻고 거기서 SD는 78.6%로 SP의 73.6%보다 높다. 한 표면이 고립 상황에서는 따르기 쉬우면서도 정면 충돌에서는 질 수 있으므로, E0 순위는 우선순위에 대한 진술이고 패널 비율은 난이도에 대한 진술이다.

## 🔬 신뢰도: 모델 간 패턴은 안정적이고 순위 마진은 그렇지 않다

prior 정렬 격차는 완전히 결정론적인 부분집합에서도 12개 모델 전부에 대해 양수로 남고, 5,013개 적격 판정에서 평균 13.09포인트다. 이 부분집합이 패턴 검사·명령 검사 계열을 과대표집하기 때문에 패널 전체의 5.81포인트보다 크다. 재검사 ICC는 모델 간 0.725, 에이전트–아이템 셀 간 0.599다. 릴리스된 3표 구성이 아니라 5표 구성으로 실행된 이전 사람 기준 감사는 919개 행에서 69.0% 일치($\kappa = 0.515$)를 보였다.

판정자를 바꾸면 판정은 훨씬 덜 안정적이다. 116개의 짝지어진 깨끗한 판정에서 일치율 62.1%, $\kappa = 0.163$이다. 판정 행의 86.8%가 판정자를 거치므로 이것이 측정에서 지배적인 불확실성이고, 그래서 논문은 모델 간 패턴을 보고하고 표시된 순서를 점 추정 랭킹으로 다룬다. $n = 65$개의 공통 비오류 표본에서 Claude–GPT 간 LLM 일치는 $\kappa = 0.4717$이며, 이것은 사람에 의한 검증이 아니다.

| Stratum | ICC(1,1) |
|---|---|

| Cell-level (agent × item) | 0.599 |

라운드 간 분산은 셀 수준에서 상당하다. 세 라운드에 걸친 셀별 Acc 범위의 평균은 15.6포인트로, 리더보드 전체의 13.7포인트 폭을 넘는다. 따라서 인접 모델 간 단일 라운드 비교는 정보가 없고, 보고된 모든 수치는 세 라운드를 합친 값이다.

**판정자 교체 ablation(GPT 5.2 대신 Claude Opus 4.7)**: family × modality × prior 셀에 걸쳐 균형 잡힌 200개 판정 부분집합을 같은 3표 프로토콜로 Claude Opus 4.7에게 다시 판정시켰다. 두 판정자 모두 116개 행에 대해 깨끗한 pass/fail/partial 라벨을 냈고, 84개 행은 한쪽이라도 no-opportunity이거나 오류이거나 증거가 없어 짝지은 비교에서 빠졌다. 짝지은 부분집합에서 원 일치율은 62.1%, 코헨 $\kappa = 0.163$이며, 에이전트별 통과율 차이는 −40pp(Seed)에서 +33pp(Kimi, MiniMax)까지 걸친다. 유지된 릴리스는 판정자 교체 집계 요약은 포함하지만 행 수준 교체 판정은 포함하지 않아, 대체 판정자 기준의 prior 정렬 격차는 구할 수 없다.

**모델 클러스터**: 릴리스에 기록된 두 클러스터 분류(빌드 5개 대 7개)에서 평균 정확도는 +5.9포인트 차이(81.2% 대 75.3%), 평균 AP-Acc는 +5.5포인트 차이(75.1% 대 69.7%)다. 따라서 prior 통제는 클러스터 차이를 설명하지 못한다 — 비교를 against-prior 규칙으로 제한해도 격차가 거의 그대로다. 적격 판정이 20개 이상인 16개 셀에서 빌드별 modality × surface 프로파일 벡터 간 쌍별 코사인 유사도는 [0.987, 0.999]에 머물러, 클러스터들은 준수 프로파일의 모양이 아니라 수준에서 다르다. 그래서 논문은 이들을 이산적인 에이전트 유형이 아니라 약한 행동 그래디언트로 다룬다.

### 🧬 prior 라벨 계보와 프로브 코호트 중첩

현재 관리되는 분포는 align-prior 115, against-prior 282, neutral 245다. 복구 가능한 5/9 zero-injection 합의는 287개 규칙을 덮고(106/170/11), 별도의 이력 보고서가 서술하는 280-규칙 이진 확정 부분집합(114/166)은 합의 개수와도 최종 282개 against-prior 라벨과도 서로 바꿔 쓸 수 없다. 계보는 275개 규칙에서 zero-injection 합의와 일치하고, 331개에서 복구 가능한 기존 값과 일치하며, 36개는 불명이고, 12개 최종 라벨은 보존된 재정의 사유 없이 복구 가능한 합의와 다르다.

against-prior 집합이 부분적으로 관찰된 모델 행동에서 정의되므로, 그 행동이 채점 대상 모델과 얼마나 겹치는지를 명시한다. zero-injection 투표는 고정된 계보 스냅숏에 기록된 아홉 빌드 프로브 코호트에서 온다. 평가된 12개 모델 중 일곱 — Claude Haiku 4.5, GLM-5.1, GPT-5.5, Hy3, Kimi K2.6, Qwen 3.6 Max, StepFun-3.5 — 은 그 코호트에 없으므로 prior 라벨에 기여하지 않았다. against-prior 격차는 이 일곱 전부에서 양수이며 평균 +5.63포인트(범위 +3.62에서 +7.19)로, 프로브 빌드와 식별자를 공유하는 다섯의 +6.06포인트와 대비된다. 두 그룹 간 0.43포인트 차이는 효과 자체에 비해 작고 12개 모델로는 어느 방향으로도 해상되지 않으므로, 논문은 이를 독립성의 증거가 아니라 경계로 보고한다.

두 가지 추가 한계가 있다. 평가 패널의 식별자 집합 바깥에 있는 프로브 빌드가 넷뿐이므로 5/9 합의에는 필연적으로 최소 한 개의 중첩 빌드가 포함되고, 따라서 어떤 zero-injection 라벨도 채점 코호트와 독립적이지 않다. 그리고 프로브 코호트에 없다는 것이 벤더 독립을 뜻하지도 않는다 — GPT-5.5, Kimi K2.6, Qwen 3.6 Max는 프로브 모델의 후속 빌드라, 같은 벤더의 프로브 빌드가 전혀 없는 평가 모델은 GLM-5.1, Hy3, StepFun-3.5뿐이고 이들의 평균 격차는 +4.99포인트다. 노출을 실제로 한정하는 것은 라벨 출처 자체다. 19,449개 against-prior 적격 판정 중 8,574개(44.1%)가 zero-injection 합의에서 온 라벨을 달고 있고, 9,051개(46.5%)는 기존 큐레이션에서, 1,824개(9.4%)는 계보 불명에서 온다. 따라서 AP-Acc 분모의 절반 미만만이 중첩의 영향을 받을 수 있다.

논문식 이진 방정식 아래, 고정된 전체 패널은 37,616개의 적격 pass/fail 판정을 담고 그중 19,449개가 against-prior다. 결과로 나오는 에이전트-macro 평균 Acc–AP-Acc 격차는 +5.8076포인트이고 12개 에이전트 전부에서 양수다. 결정론 전용 부분집합은 5,013개 적격 판정(against-prior 977개)을 담고 +13.0933포인트를 주며, 역시 모든 에이전트에서 양수다. 더 큰 이력 추정치들은 보존되지 않았다. 가용한 임계값 스윕은 복구 가능한 zero-injection 합의 부분집합을 다시 라벨링한다. 같은 이진 정의 아래 평균 격차는 4/9와 5/9에서 +11.8161포인트, 6/9에서 +10.6022, 7/9에서 +10.2438이고 4/9–6/9 변화는 1.2139포인트다. 따라서 방향은 시험된 임계값들에 걸쳐 안정적이다.

**공통 지지 불확실성**: 공통 지지는 같은 (아이템, 라운드, 규칙) 키에 대해 모든 모델이 깨끗한 pass/fail 결과를 내기를 요구한다. 3,342개 고유 관측 중 2,430개(72.7%)를 남기고, 여기에는 58개 아이템에 걸친 1,214개의 against-prior 관측이 포함된다. 결정론적인 2,000회 재표집 아이템 클러스터 백분위 부트스트랩(시드 20260723)을 쓰고, 표집된 각 아이템 안의 공통 지지 라운드와 규칙 행을 모두 유지한다. 짝지은 Acc–AP-Acc 구간은 모든 모델에서 양수이며 하한은 +1.06에서 +4.83포인트에 걸친다. 반면 인접한 공통 지지 Acc 구간은 전부 0을 포함해, 12개 모델 전부를 담는 보수적인 인접 동률 그룹 하나가 나온다. 즉 prior 정렬 대비는 모델별로 해상되지만 이웃한 점 순위는 그렇지 않다.

## 🧾 실패 갤러리

고정된 채점 패널에서 뽑은 다섯 개 실패가 벤치마크의 주요 발견을 예시한다. 원천 추상화를 유지하려고 이 사례들은 안정적인 라이브러리 식별자나 축자 제약 텍스트 대신 논문 내부 라벨과 행동 패러프레이즈를 쓴다.

**예시 A: 스킬 표면 배치 누락.** 두 에이전트가 요청된 스킬 산출물을 만들었지만 요구된 프로젝트 관례 바깥에 놓았다. 같은 규칙이 프로젝트 파일로 전달됐을 때(적격 판정 144개 중 100%) 스킬 설명으로 전달됐을 때(103개 중 67.0%)보다 더 자주 지켜졌다. 이들은 균형 배치된 쌍이 아니라 서로 다른 아이템의 서로 다른 규칙 인스턴스이므로 이 대비는 서술적이다.

**예시 B: 도구 표면 워크플로 누락.** 워크플로 규칙이 도구 설명에 나타났을 때 한 에이전트가 요구된 구조화 형식 대신 자유 형식 변경 요약을 냈다. 이 패널에서 그 규칙은 도구 설명에만 놓이고 거기서 172개 적격 판정 중 91.9%로 지켜지므로, 이것은 표면에 대한 증거가 아니라 대체로 잘 지켜지는 규칙에서의 인스턴스 실패다.

**예시 C: against-prior 출력 실패.** 명시적 금지에도 불구하고 두 에이전트가 추가 문서 산출물을 생성했다. 과제가 자연스럽게 설명적 출력을 유도했기 때문에, 준수하려면 요청된 구현을 완료하는 것을 넘어 흔한 기본값을 눌러야 했다.

**예시 D: output control 미러링.** 한 에이전트가 주변 픽스처의 언어와 서식 단서를 최종 응답에 그대로 옮겨 응답 언어 제약을 위반했다. 이는 output control 계열에서 흔한 표면 미러링 패턴을 반영한다.

**예시 E: 예산 초과.** 두 에이전트가 명시된 크기 상한을 크게 넘는 산출물을 만들었다. 제약 없는 생성이 더 긴 출력을 선호할 때 수량 제약에서 실패하는 모습을 보여준다.

## 🌐 도구는 코드 밖으로 이전되지만 순위는 그렇지 않다

별도의 탐색적 패널이 같은 12개 빌드의 1,428개 유효 궤적으로 다섯 도메인 40개 비코딩 케이스를 채점한다. case-macro 통과율은 65.8–84.8%에 걸치고, 코딩 리더보다 GPT-5.5가 앞선다. 그 패널의 지표와 모집단은 다르며 코딩 결과와 결코 통합되지 않는다.

프로토콜은 이렇다. 다섯 도메인은 고객 지원, 법무/컴플라이언스, 마케팅 콘텐츠, 재무 분석, 연구/학술 글쓰기이고 각 도메인에 여덟 케이스다. 12개 모델이 케이스당 세 번의 생성 런을 받아 1,440개 궤적을 시도했다. 이 과제들은 저장소 패치가 아니라 주로 자연어 산출물을 만들기 때문에, 언어·도구·상호작용 지평·규칙 존재론이 코딩 패널과 다르다. 모델 빌드는 고정된 Stage-5 평가가 기록한 것이지 이후 패널에서 같은 이름을 가진 빌드와 반드시 같지는 않다. 두 행은 Stage-5 표시 이름 Hunyuan 3와 StepFun Flash를 쓰는데, 이는 코딩 리더보드의 Hy3와 StepFun-3.5에 대응한다.

지표는 이렇다. 케이스 $c$, 모델 $m$의 채택된 런 $r$에 대해 $E_{cmr}$을 평가의 제외 처리 후 남은 적격 규칙 판정이라 하고 $p_{cmr} = |E_{cmr}|^{-1} \sum_{j \in E_{cmr}} \mathbb{1}[j = \text{pass}]$라 하자. 먼저 각 케이스–모델 쌍의 유효 런들에 대해 $p_{cmr}$을 평균하고, 그다음 40개 케이스 평균을 동등하게 평균한다.

$$\text{NC-Macro}_m = \frac{1}{40} \sum_{c=1}^{40} \frac{1}{|R_{cm}|} \sum_{r \in R_{cm}} p_{cmr} \quad (5)$$

이 case-macro 구성은 루브릭 검사가 더 많은 케이스가 지배하는 것을 막는다. 빈 껍데기 궤적은 제외되고, 판정자 오류가 25% 이상인 비어 있지 않은 궤적은 고정된 평가 프로토콜에 따라 깨끗한 적격 규칙 비율을 쓴다. Table 8의 신뢰구간은 20,000회 고정 시드(20260714) 도메인 층화 부트스트랩 반복에서 나온 백분위 구간으로, 각 도메인 안에서 케이스를 재표집하고 표집된 케이스의 관찰된 런 집계를 유지한다. 재표집 단위는 런이나 개별 규칙 판정이 아니라 케이스다.

## ⚠️ 저자들이 인정하는 한계

**범위.** Harness-IF는 멀티턴 코딩 에이전트를 겨냥한다. 평가된 60개 아이템은 80개 작업 세트에서 품질·변별력 검토를 거쳐 선정됐고, 라이브러리의 642개 규칙 중 302개를 인스턴스화해 256개를 채점한다. professional-writing 규칙은 비코딩 확장에서만 사용된다. 따라서 주장은 이 아이템과 모델 패널에 대해 성립하며, 40개 케이스 비코딩 확장은 별도의 case-macro 지표 아래 보완적인 폭을 제공한다.

**측정.** AP-Acc는 관찰되거나 큐레이션된 기본값에 대한 행동적 층화이지 모델 학습 출처에 대한 주장이 아니다. 부록에 라벨 계보를 보고하며 여기에는 zero-injection 프로브 코호트와 평가 패널의 중첩이 포함되고, 전 구간에 하나의 like-for-like 이진 정의를 쓴다. 판정의 86.8%가 판정자 교체 시 라벨이 달라지는 LLM 판정자를 거치므로, 절대 수준은 도구 특유의 것이고 도구를 공유하는 모델 간 비교가 주장을 짊어진다. F-Acc와 DW-Acc는 코호트 적응형 진단이고, 공통 지지와 아이템 클러스터 분석이 주 분모와 불확실성 검사를 맡는다. 실패 분해는 위반을 규칙이 무엇을 요구하는지로 묶으므로 잠재적 인과 메커니즘이 아니라 규칙 구조를 서술한다.

**해상도와 표면.** 교정과 재검사 분석은 벤치마크의 모델 간 패턴은 뒷받침하지만 이웃한 모델 간의 미세한 구분은 뒷받침하지 않는다. 메인 패널은 현실적 커버리지를 위해 규칙을 운영상 허용 가능한 표면에 놓고, 통제된 비교는 E0가 따로 제공한다. E0의 통합 순서는 교차 부트스트랩·방향·삭제·가중·오류 분석 전반에서 견고하지만, 보편적 위계가 아니라 E0 안의 빌드 간 경향으로 해석된다.

이와 별개로 저자들은 다음도 인정한다. 메인 코딩 패널은 짝지은 표면 개입을 제공하지 않는다 — 제약은 모든 배치에 균형 배치되는 대신 허용 가능한 표면에 배정되고, 표면 표현과 계열 구성이 함께 변할 수 있다. 그래서 그 표면×계열 셀은 분산 분해나 통제된 표면 효과가 아니라 서술적 층으로 다뤄진다. 이력상의 held-out 분석이 648개의 추가 충돌 런과 켄달 $\tau$, 그리고 89%의 강한 그룹 승률을 보고하지만 그 행 수준 산출물은 보존되지 않아, 저자들은 이를 견고성 결과가 아니라 서술적 이력 증거로만 다룬다.

Datasheet의 **알려진 편향**도 저자들의 인정이다. 제약 라이브러리는 영어권·소프트웨어 엔지니어링 중심의 수작업 조사에 표적 확장을 더한 것을 반영하고, 자유 형식 출처 라벨은 저장소 표집 프레임을 확립하지 않는다. 12개 에이전트 평가 표본은 작성 시점에 일반 이용 가능한 상용·공개 API 모델로 구성되며, 코딩 전용 특화 모델이나 fine-tuning된 변형은 포함하지 않는다. 코딩 아이템 선정에 관찰된 파일럿/전체 패널 변별력·난이도 진단을 썼기 때문에 관찰된 모델들 사이의 분리를 선호할 수 있다(선택 낙관). 모델 행동에서 보이는 학습 출처 대응은 인과가 아니라 서술적으로 해석해야 한다. 전처리 쪽에서는, 유지된 증거가 구성 시점의 포괄적 중복 제거나 PII 제거 주장을 뒷받침하지 않는다고 명시한다. 사람 기준 교정에 대해서는, 행렬 산술과 케이스별 불일치 사유는 유지되지만 원시 결합 라벨, 표집 프레임과 확률, 평가자 배정, 독립 조정 기록이 유지되지 않아 완전히 감사 가능한 사람 교정 연구가 아니며 한정된 증거로만 보고한다고 밝힌다.

## 🧷 결론과 저자들의 권고

Harness-IF는 운영상의 지시 준수를 개별 규칙과 전달 표면 수준에서 측정 가능하게 만든다. 60개 멀티턴 코딩 아이템, 256개 채점 규칙, 12개 프런티어 모델에 걸쳐 모든 모델이 전체 패널 분석과 공통 지지 분석 양쪽에서 against-prior 규칙에 더 취약하며, 이는 총계 점수가 가리는 준수 차이를 드러낸다. 벤치마크는 나아가 계열과 양상별로 실패 서명을 국소화하고, 균형 배치된 E0 연구는 시스템 프롬프트·프로젝트 파일·사용자 지시가 도구 설명과 스킬 설명을 앞서는 견고한 통합 순서를 식별한다.

저자들의 권고는 이렇다. 코딩 에이전트 평가는 지시 준수를 실행 수준의 대상으로 다뤄야 한다 — 규칙 출처를 보존하고, 개별 기회를 채점하고, against-prior 행동을 총계 성공에서 분리하고, 우선순위 주장을 할 때는 전달 표면을 균형 배치할 것.

**공개**: 벤치마크는 자족적 패키지로 공개 준비되어 있다. YAML로 된 642-규칙 제약 라이브러리, 시나리오 픽스처와 정답 채점 스크립트를 갖춘 60개 조립 코딩 아이템, 여기 보고된 모든 수치 뒤의 2,160-레코드 판정 패널, 평가·분석 코드가 들어간다. 스크립트 하나가 배포된 판정 레코드에서 표시된 각 그림과 표를 다시 계산하므로, 이 논문의 결과는 모델 API 접근 없이, 에이전트를 다시 돌리지 않고 오프라인에서 재현할 수 있다. 새 모델을 평가하려면 추가로 코딩 에이전트 harness와, 시험 대상 모델 및 판정 모델 양쪽에 대한 API 접근이 필요하다. 프로젝트가 작성한 소프트웨어는 Apache-2.0, 프로젝트가 작성한 벤치마크 텍스트·데이터와 정제된 파생 결과는 CC-BY-4.0으로 공개된다. 원시 제공자 출력과 에이전트 런 작업 공간은 재배포하지 않는다. 공개 위치는 이 프리프린트의 이후 버전에서 주어진다. 픽스처 785개 파일에 대한 기계적 출처 감사에서 복사된 제3자 자료가 발견되지 않아 2026-07-27 소유자 확인이 이뤄졌고, 크라우드워커는 쓰지 않았다. 용도는 코딩 에이전트의 지시 준수 성능 벤치마킹과 표면 인식·prior 인식 평가 방법론 검증이며, 인증 도구나 에이전트 역량 인증, 채용/조달 결정 도구로 의도되지 않았다.

**원본 소스가 PDF 경로로 변환돼 수식과 그림이 유실됐다.** 소스 frontmatter는 `route: pdf`, `known_losses: [math, figures]`, `verified: no`로 기록돼 있다. 실제로 이 노트의 식 (1)–(5)는 소스에서 문자열이 뒤섞인 상태로만 남아 있어(분자·분모·첨자가 줄 밖으로 튀어나옴), 남아 있는 기호와 본문 정의로부터 형태를 되살려 적었다. 원 논문의 조판과 다를 수 있다. 마찬가지로 그림 7개는 이미지가 하나도 남지 않았고, Figure 1·2·3·4·5·6·7의 내용은 캡션과 그림 안 텍스트 조각으로만 존재한다. 그래서 이 노트에는 임베드된 그림이 없고, Figure 3의 구성 비율과 Figure 4·5의 막대 수치는 본문이 같은 값을 활자로 반복하는 경우에만 옮겼다. Table 1도 열 정렬이 무너져 있어 내가 헤더 설명에 맞춰 재조립했다.

**논문 곳곳에서 값 일부가 소스에 남지 않았다.** 부록 D.5의 켄달 $\tau$ 값은 소스에서 "τ = 0."과 "91"로 끊겨 있어 0.91로 읽히지만 확정할 수 없다. 부록 E.1의 auto-vs-Claude 및 auto-vs-GPT 일치 계수도 "0491", "0.0332", "− 0."처럼 잘려 있어 이 노트에는 옮기지 않았다. 본문이 명시하는 $\kappa = 0.4717$(n=65)와 $\kappa = 0.515$(919행, 69.0% 일치)만 옮겼다. 사람 기준 감사의 3클래스 혼동 행렬 크기도 "515"라는 숫자 조각만 남아 원 문장을 복원할 수 없었다.

**Table 2의 볼드 표시는 캡션의 규칙에서 유도한 것이다.** 소스의 표 마크업이 깨져 볼드 정보가 사라졌지만, 캡션이 "bold marks each column's best value"라고 말하고 Claude-Opus-4.7이 Acc·F-Acc·DW-Acc·AP-Acc 네 열에서 모두 최고값이므로 그 행에만 볼드를 붙였다. $\Delta$ 열은 최고값 표시 대상인지 캡션이 말하지 않아 표시하지 않았다.

**소스 본문에 중복 문단이 있다.** 부록 D.4의 마지막 두 문단은 같은 내용("The pooled ordering survives both direction-specific fits…"으로 시작하는 부분)을 거의 그대로 반복하는데, 한쪽은 "ordering", 다른 쪽은 "tier ordering"으로 표현이 미세하게 다르다. PDF 변환 중복인지 원 논문의 중복인지 소스만으로는 판별되지 않아, 이 노트에는 한 번만 옮겼다.

**AP-Acc가 순위를 바꾸는 폭과 논문이 순위에 대해 하는 주장 사이에 긴장이 있다.** 논문은 prior 통제가 인접 순위 쌍 세 개를 맞바꾼다는 점을 결과로 제시하면서, 동시에 공통 지지 분석에서는 모든 인접 Acc 구간이 0을 포함해 12개 모델 전부가 하나의 동률 그룹이 된다고 말한다. 두 서술이 서로를 부정하지는 않지만 — 앞은 점 추정 랭킹, 뒤는 구간 — 노트를 읽는 사람이 "순위가 바뀐다"를 통계적으로 해상된 결과로 읽지 않도록 두 문장을 함께 봐야 한다. 논문 본문은 이 둘을 한 문단 안에서 나란히 놓지는 않는다.

**표면별 정확도(Table 4)와 E0 표면 순위(Figure 6)는 서로 다른 것을 재는데, 논문이 그 점을 명시한 곳은 부록 D.4다.** 본문만 읽으면 SD가 메인 패널에서 78.6%로 SP(73.6%)보다 높은데 E0에서는 마지막이라는 사실이 충돌처럼 보인다. 부록이 "고립 상황의 난이도"와 "충돌 시 우선순위"를 구분해 해소한다.

**UI 표면의 54.5%는 다른 표면 수치와 나란히 놓고 읽을 수 없다.** 논문 자신이 각주로 밝히듯 이 패널의 UI 배치는 1,476개 전부가 against-prior다. 그래도 표 안에서 가장 낮은 자리에 있어 시각적으로는 "사용자 지시가 가장 안 지켜진다"로 읽히기 쉽다. 이 노트에서는 각주를 표 바로 아래 본문으로 끌어냈다.

**zero-injection 라벨의 독립성 문제를 논문이 스스로 닫아 두었다는 점은 기억할 만하다.** 프로브 아홉 빌드 중 다섯이 평가 패널과 식별자를 공유하고, 패널 밖 빌드가 넷뿐이라 5/9 합의에는 반드시 중첩 빌드가 하나 이상 들어간다. 저자들은 이를 감추지 않고 "어떤 zero-injection 라벨도 채점 코호트와 독립적이지 않다"고 쓴다. 다만 AP-Acc 분모의 44.1%만 그 경로에서 라벨을 받는다는 사실이 노출 상한 역할을 한다는 것이 저자들의 논거이고, 나머지 46.5%의 "기존 큐레이션" 라벨이 어떤 절차로 만들어졌는지는 소스 범위 안에서 더 구체화되지 않는다.
