# Harness Spec — Claude Researcher

## Context

Single-developer project (성진). The repo is the future home of a "veteran researcher assistant" harness: Claude discusses AI research and paper writing with 성진 through `AskUserQuestion`. The first component is `save-paper`, which fills the knowledge base under `papers/`.

Language: Python 3.12 scripts (bs4, lxml, requests, yaml already installed; no new dependencies), plus brew tools pandoc 3.10 and poppler, plus `npx @firecrawl/anydoc` for the PDF fallback. Tests: pytest under `tests/<component>/` at the repo root. No `pyproject.toml`. Harness prose is written in English (성진's decision); the Korean note output is in Korean. 성진 uses Claude Code vocabulary fluently, so the interview can name layers directly.

Distribution: this repo only. Not packaged as a plugin — the skill depends on brew tools and on the `papers/` path, so it would not travel anyway. (Assumed in the plan session, not explicitly confirmed by 성진.)

`AGENTS.md` is a symlink to `CLAUDE.md`, so both agents read one file.

**Research harness (2026-09-06, second pass).** On top of the knowledge base, 성진 does empirical AI research (experiments included) and writes the paper; Claude is the veteran-researcher assistant who supplies grounds for judgments and criticises 성진's, never the autonomous researcher. Facts 성진 fixed in the plan session: target venue is a main-track conference from the start (a workshop is a later "lowering" decision, not a redesign; arXiv alone is weak for graduate admissions and the interviewer will ask about the paper); resources are LLM API keys, this Mac (CPU/MPS) and cloud GPUs that 성진 procures on demand, so the experiment layer registers, seals and verifies results rather than running them per resource; `AskUserQuestion` only where the paper's claim changes or 성진's money or time is spent, everything else Claude decides and records; authorship — hypotheses, research questions, experiment-design sketches, the introduction's contribution claims and the conclusion are written by 성진 first, code by Claude, methods/related-work/results prose drafted by Claude from the ledgers, and a viva (Claude picks claims at random and 성진 explains them) gates submission; language — decision ledgers and reviews in Korean (성진 reads them back), claims in English (they become paper sentences and codex packets), harness prose in English; critic recall evaluation with real codex runs is part of the implementation; distribution stays this repo only; delegation and verification go to codex (gpt-6-astra) first. Machine facts: codex-cli 0.153.4, Claude Code 2.1.263, Python 3.12 with numpy/scipy/pandas/matplotlib, no LaTeX (brew has a tectonic bottle).

## Goals

Save one arXiv paper as (1) a faithful, completeness-checked Markdown source under `papers/sources/<id>.md` with figures as PNG and provenance frontmatter, produced by a deterministic script, and (2) for papers 성진 chooses to study, a Korean restructured note under `papers/<id>.md` written by an opus subagent. Interpretation, summary, and cross-paper synthesis are out of scope here and belong to the research harness proper.

Quality bar for the source layer, in 성진's words: **strict on completeness, loose on formatting.** Paragraphs, table cells, equations, figures and references must all be present (machine-checked); line breaks, escape residue and empty table headers are left alone, because the reader of the source layer is an LLM.

**Research harness.** Three premises 성진 brought and the answer to each. (1) Critical honesty is placed in interfaces, not prose: Harness-IF (2608.11727, saved here) measured that rules against a model's default disposition are followed less than the average rule on all 12 models, so "be honest and critical" is one CLAUDE.md paragraph and the force sits in a decision ledger that records the recommendation *before* asking and requires "what breaks if this option is wrong" per option, in codex reviews bound as preconditions (by artefact hash) to confirmatory runs and the final build with a per-finding disposition log, and in deterministic verification (numbers only through registry macros, citations only through a bibliography check). (2) Convergence to the mean is a context problem and the answer is accumulation: `projects/<slug>/` accumulates decisions, claims, literature, runs and reviews as OKF-frontmatter files and a session starts from one `status` screen; because accumulation alone does not undo anchoring, rejected alternatives stay as `dropped` and go into every review packet. (3) Questions attach to decisions, not phases: a decision Claude made alone is still in the ledger with `asked: false`, so "decided silently" becomes "visible later".

## Component specs

### B1 `save-paper` skill

Readers: the Claude running the skill and 성진. Body target 60–90 lines, English. Sections: why two layers exist; Run (one command, `--help` is the source of truth for flags and exit codes); What the result means (exit 6 = saved but unverified, `route: pdf` = no math or figures, how to read `verified`); Decisions that are the user's (ambiguous title search, overwriting on a new version, turning on `--describe`, making a note); Korean note (what to hand `paper-note`, then `note-check` and `index`); Traps (project-specific only). No flag table, no install instructions (`doctor` says them), no architecture.

`allowed-tools: Bash(python3 .claude/skills/save-paper/scripts/save_paper.py *)` — one pre-approval, matched on the literal command text, so the skill body tells Claude to run exactly that relative form from the project root. The plan's `${CLAUDE_PROJECT_DIR}` form was dropped: that variable is empty inside the Bash tool, so the pattern could never match a working command. The script downloads only from `https://arxiv.org/`, writes only under `papers/`, and publishes atomically, so the prompt buys nothing and would fire once per paper in a batch. Treated as approved with the plan.

### B2 `save_paper.py` CLI and `savepaper/` package

Subcommands: `save`, `batch`, `describe`, `resolve`, `check`, `index`, `note-check`, `doctor`. Every argument carries `help=`; closed spaces use `choices=`. Exit codes: 0 ok / 2 usage / 3 resolve failed or ambiguous / 4 fetch failed / 5 convert failed / 6 saved but coverage check failed / 7 doctor or describe prerequisites missing.

Pipeline: resolve (URL, id, legacy id, or title → one exact `vN` and metadata from `export.arxiv.org/api/query`) → fetch into a staging directory (HTML at `arxiv.org/html/<id>v<n>`, e-print tarball for figure originals, PDF only on the `pdf` route) → LaTeXML DOM adapter (bs4) → pandoc `-f html -t gfm-raw_html-tex_math_gfm+tex_math_dollars` → coverage check against the original DOM → optional describe → frontmatter → atomic rename into `papers/sources/` → regenerate `papers/README.md`.

Modules: `arxiv.py` (ref parsing, Atom parsing, version pinning, 3 s process-wide rate limit honouring `Retry-After`, fetch), `latexml.py` (DOM adapter), `assets.py` (safe tarball extraction, `pdftoppm -png -r 110`, PNG/JPG copy, SVG fallback), `pandoc.py`, `pdfroute.py` (anydoc), `describe.py` + `describe_prompt.md`, `check.py`, `frontmatter.py`, `index.py`, `publish.py`, plus `errors.py` (exceptions carrying the exit codes), `pipeline.py` (the `save` transaction) and `notecheck.py` (`note-check`), added during implementation because the CLI file would otherwise hold the orchestration.

Security: tarball members with path escape or symlinks are refused; 50 MB per file and 500 MB total caps (`# 성진:` comment marks the limit); figure types confirmed by magic bytes; download URLs must start with `https://arxiv.org/`.

Coverage check: ordered content blocks from the untouched DOM (every `.ltx_p`, table cell, caption, `.ltx_bibitem`, footnote body, `ltx_listingline`, math annotation TeX) are normalised and looked up as substrings in the normalised Markdown. Any missing paragraph, caption, bibitem or table cell fails; unparsed math is a warning. Failure still saves the file, without `verified`, with `conversion.coverage` and `known_losses`, exit 6. The check guarantees fidelity to the HTML received, not that the HTML is the whole paper; the tarball `\bibitem` count is compared as a warning.

### B2a note step (`savepaper/note.py`, 2026-09-06)

`write_note(source, target, runner=, project_root=, log=, run=)` runs the agent headlessly with the prompt on stdin: the two absolute paths plus the conversion facts read from the source frontmatter (route, verified, coverage, known losses, up to 20 missing-block previews, count of empty alts). No rule travels in the prompt; the body owns them. Claude runner: `claude -p --agent paper-note --output-format json --permission-mode dontAsk --allowedTools Read Write "Bash(python3 .claude/skills/save-paper/scripts/save_paper.py note-check *)"`, no `--model` (measured: the agent file's `model: opus` beats the settings default, an explicit `--model` beats the file, so the file stays the single owner). Codex runner: `codex exec -s workspace-write -m $CODEX_MODEL --ephemeral` with the agent body pasted in front. The agent writes to `papers/.staging/notes/<id>.<runner>.md`; the script re-stamps `generated.by` with the real runner/model, runs `note-check`, and `os.replace`s into `papers/<id>.md` — a failure never touches the previous note. Outcomes: `written | kept | skipped | failed | refused`, with `error` = `auth | denied | crash | timeout | refused | nofile`; claude falls back to codex once on `refused`/`nofile` only. `note_for` decides from the save status: (re)saved → always; `up-to-date` → only if no note; `new-version-available` → skip. `batch` submits each note to a thread pool the moment its source is published (cap `NOTE_CONCURRENCY`, default 3); README is written by the main thread only, once at the end, because `write_index` is a non-atomic full rewrite.

### B3 `paper-note` agent

`name: paper-note`, `tools: Read, Write, Bash`, `model: opus` — pinned because long-form Korean rewriting fidelity is the whole value; one run per saved paper, launched in parallel when several papers are saved together. No `memory`. The body is a full system prompt: restructure, never summarise; substance 100 %, scaffolding dropped; numbers, equations and tables verbatim; author-acknowledged limits and note-writer-observed boundaries in separate sections; figures read from the PNGs with `Read`, embedded as `![](sources/images/...)`; reference list not copied, in-text citations kept author-year; 평어체; Markdown limited to headings, bold, code, images, tables. Output: frontmatter (`type: Paper Note`, `sources`, `generated`, `status: draft`, `tags`, `related`) then `# 🖇️<Korean title>`. Ends by running `save_paper.py note-check` and reporting its output verbatim. Undecided points are returned as results, since `AskUserQuestion` does not exist in a subagent.

### B4 `CLAUDE.md`

About five lines: what the two layers under `papers/` are and which to read when, that `papers/README.md` is generated and never hand-edited, and that saving a paper goes through `/save-paper`. No inventory.

### B5 `describe.py`

OpenRouter chat completions, model `openai/gpt-5.6-luna`, `reasoning.effort: high`, `max_tokens: 16000`, `provider: { require_parameters: true, sort: price }`, JSON-schema response `{description}` — values measured in 성진's `generate_description.js`. Key `OPENROUTER_API_KEY` and optional model `OPENROUTER_MODEL` from the environment, then `scripts/savepaper/.env` beside the code (성진's preference; `.env.example` committed there), then a project-root `.env`. Without a key `save` warns and leaves the alts empty; only `describe <id>` exits 7. Prompt in `describe_prompt.md` next to the code, adapted from 성진's `prompt_description.md`. Writes the alt slot of `![alt](path)` only; failed images keep an empty alt and are counted in `figures_described.failed`. On by default in `save` and `batch` (`--no-describe` opts out) since 2026-09-06.

### B6 `research` skill

Readers: the Claude running a research session and 성진. Body 80–110 lines, English. `description` is trigger-first (연구하자, 실험, 논문 쓰자, 리뷰해줘, 가설, hypothesis, experiment, paper draft, review my claim) with the near-misses named: saving a paper is `save-paper`, web search is `ultra-search`. `allowed-tools: Bash(python3 .claude/skills/research/scripts/research.py *)` — the same relative form as `save-paper` (measured there: `${CLAUDE_PROJECT_DIR}` is empty in the Bash tool). Body: a session opens with `status <slug>` and closes by updating `project.md`'s `phase`; the question protocol (`decide propose` first, then `AskUserQuestion` with ≤4 options each naming what changes, then `decide resolve`; a decision Claude makes alone is still recorded with `asked: false`); disposition rules (no scores; `reject` needs a registry or source reference; disagreement with 성진 is `human`); exploration mode (no "shall I tidy this up?" while 성진 is still diverging); authorship (Claude's candidate hypotheses go in as `claim add --by claude`; 성진's are `by: human` and immutable); debate only as `ideate`'s structured rounds, run after 성진 has written their own hypothesis; traps (README is generated, `runs/` is denied, conference templates must be verified at their current version with `ultra-search`). No flag table, no exit-code table: `--help` owns both.

### B7 `research.py` CLI and `research/` package

Conventions inherited from `save_paper.py`: argparse subcommands, `help=` on every argument, `choices=` for closed spaces, exit-code constants in `research/errors.py` on a separate `ResearchError` hierarchy, `--json` on every command printing `{status, paths, findings, error}`. Exit codes: 0 ok / 2 input error (missing field named by path) / 3 project, file or reference not found / 5 subprocess failed (tectonic, codex, claude, experiment; child code reported separately) / 6 verification failed or gate blocked / 7 prerequisite tool missing. Project root: `--root` > `CLAUDE_PROJECT_DIR` > cwd. Reuse from the sibling skill is exactly `savepaper.frontmatter` (`parse`/`dump`) and `savepaper.describe.load_setting`, imported after `research.py` puts the sibling `scripts/` on `sys.path` from `Path(__file__).resolve()`; `index.build_index`, `pipeline.py` and `note.py` carry paper policy and are not reused (codex contract review). Settings: `research/.env` beside the code, then the project-root `.env`. Tests import the CLI as `research_cli` because `research.py` and `research/` share a basename.

Project directory contract (`research.py init <slug>`, slug lowercase kebab): `project.md` (`type: Research Project`; `question`, `phase` ∈ exploring|designing|running|analyzing|writing|reviewing|submitted, `venue`, `submission_ready: false`), `README.md` (generated index over every `.md` frontmatter and `run.json`, rewritten by every writing command), `decisions/<NNN>-<slug>.md` (Decision, Korean), `claims/<CNN>.md` (Claim, English), `literature.md` (Literature: entries linking `papers/sources/` or, for non-arXiv, `verified: {by: human:seongjin, at}`, plus a search-boundary log), `prereg/<PNN>.md` (Preregistration: hypothesis/prediction claim bytes, analysis-plan bytes, sha256 of each, UTC), `experiments/runs/<run-id>/` (script-only: `run.json`, `output.log`, `results.json`, `artifacts/`, `seal.json` on completion), `experiments/registry.json` (generated), `paper/` (`template/`, `main.tex`, `sections/*.tex`, `refs.bib`, generated `results.tex`, `figures/<name>.py` → `.pdf` + `manifest.json`; `build/` gitignored), `reviews/<RNN>-<lane>.md` (Review: Korean body, findings JSON block, disposition log), `ideation/<INN>.md`, `viva/<VNN>.md`.

Decision file: `decide propose` writes `title`, `proposed_at`, `asked`, `options[]` (2–4, unique `label`, `fails_when` required, `evidence[]` or `evidence_gap`), `recommendation`; `decide resolve` fills `chosen`, `resolved_at`, `decided_by`, `dissent` — the order is in the file, so "recommend after hearing" is impossible. Claim: `kind` ∈ observation|hypothesis|mechanism|prediction|alternative|evidence, `by` immutable, `claim_status` ∈ candidate|supported|refuted|dropped (named apart from OKF `status`), `evidence[]` of `{registry, statistic}` or `{source, locator}`, `prereg`; `supported` requires every evidence item to resolve (exit 6); rejected claims become `dropped`, never deleted. `results.json` (written by the experiment into `$RESEARCH_RUN_DIR`): `schema_version`, `metric_def`, `conditions` with `config_sha256`, `observations[]` of `{condition, seed, metrics}` with values as strings. `run.json`: `argv`, `cwd`, allow-listed `env`, `git_sha`, `dirty_diff_sha256`, `expected_seeds`, `prereg` (null → `class: exploratory`), `design_review`, `started`/`ended`, `child_exit`, `status` ∈ completed|failed|interrupted. `seal.json`: sha256 of `run.json`, `results.json`, `output.log`, `artifacts/*`. `registry.json`: one entry per `(run_id, condition, metric)` with `values[]`, `statistics {n, mean, std}` as Decimal strings, `unit`, `class`; `inputs` with per-run hashes; `excluded_runs` with reasons.

Gates (the contract codex's design review called the one thing that must exist): `run start --confirmatory` requires `--prereg <PNN>` and a `scope: design` review whose packet hash matches the current claims and preregistration with every major finding dispositioned — missing pieces are named, exit 6; a run without `--confirmatory` is `exploratory` and `paper verify` warns when one is cited in confirmatory context. `build --final` requires a `scope: draft` review of the current draft hash with all majors dispositioned and a viva record bound to the same hash; a changed draft invalidates both (hash mismatch = exit 6). Dispositions via `review log`: `accept` (what changed), `reject` (registry/source reference required), `test` (discriminating experiment; closes only with a run id), `human` (성진's Decision id required). No scores.

Commands: `init`, `status` (phase, open decisions, claims changed since preregistration, undispositioned findings, gate readiness, recommendation=chosen and asked ratios per `decided_by` — measurements, not thresholds), `decide propose|resolve`, `claim add|update`, `prereg freeze|check`, `run start|import`, `registry [--strict] [--min-seeds]` (recompute plus sanity warnings: identical per-seed values across conditions, identical means across all conditions, too few seeds, non-finite values, missing `metric_def`), `paper init|results|figures|verify`, `build [--final]`, `review request --scope design|draft [--lane codex|claude]`, `review log`, `ideate`, `viva sample|record`, `doctor`. `review request` assembles the packet deterministically (all claims incl. `dropped`, all runs incl. excluded, all decisions incl. `dissent`, the draft or the design; omissions listed), copies it to a temp dir outside the repo, runs stage 1 (criteria pre-commitment without the packet) then stage 2 (the packet plus the lane's own stage-1 output; codex with `--output-schema`, claude with `--output-format json` validated against `review_schema.json`), and writes `reviews/<RNN>-<lane>.md` with packet hash, runner and model, both raw outputs and the findings block. Runner shape is `note.py`'s (`run=` seam; codex falls back to claude once on `refused`/`nofile` only — 성진, 2026-09-06). `ideate` assigns each lane a different evidence slice or role, runs an independent first round and one cross-critique round, and writes `ideation/<INN>.md` with per-lane raw text and the preserved disagreements; candidates go in as `claim add --by claude`, the choice is 성진's `decide`. `viva sample` picks supported claims plus one counterfactual with an injected RNG; `viva record` takes 성진's answers before Claude's assessment and binds the record to draft, claims and registry hashes.

Package: `errors.py`, `project.py`, `decisions.py`, `claims.py`, `prereg.py`, `runs.py`, `registry.py`, `paper.py`, `verify.py`, `runners.py`, `review.py`, `ideate.py`, `viva.py`, `review_schema.json`, `.env.example`.

### B8 `CLAUDE.md` addition

About twelve English lines: the two boundaries and their reason (a paper 성진 can defend in an interview; anchoring), citable evidence is `papers/sources/` and registry references only, why an edit under `runs/` or to `registry.json` is refused (provenance is a sealed run and nothing else), and that research goes through `/research`. Root CLAUDE.md because it is the only prose that is re-read after compaction; a skill body is rationed at 5,000 tokens newest-first.

### B9, B13, B14 rules

Each carries `paths:`. `research-experiments.md` on `projects/*/experiments/**`, `projects/*/claims/**`, `projects/*/prereg/**`; `research-paper.md` on `projects/*/paper/**`; `research-review.md` on `projects/*/reviews/**`. Rules rather than skill `references/` because a rule attaches the moment the matching file is read, without a routing decision.

### B10 `critic` agent

`name: critic`, `tools: Read`, `model: opus` (the value of a review is the defect it did not miss), no `memory` (a reviewer that remembers its last review is not pre-committing). Description: called headlessly by `research.py review request`; delegate directly only with a packet path attached. Body: one principle (find why a main-track committee would reject this; the author is irrelevant; proportionality; a field-norm critique must be citable), a stage-1 section (criteria without the packet) and a stage-2 section (packet plus own stage-1 output); unresolved points are returned as results because `AskUserQuestion` does not exist in a subagent. The output format is enforced by `review_schema.json`, so the body does not restate it. The codex runner pastes this body (frontmatter stripped) in front of the prompt.

### B11 permissions

`.claude/settings.json` → `permissions.deny`: `Edit(projects/**/experiments/runs/**)`, `Edit(projects/**/experiments/registry.json)`. An `Edit` rule also governs `Write`, `NotebookEdit` and the file commands Claude Code recognises in Bash (`sed -i`, redirection). It does not reach a Python subprocess, which is exactly how `research.py` writes there. Manual probe results are recorded under Validation.

### B12 recall evaluation

`tests/research/fixtures/seeded/{defective,clean}/` are two synthetic `projects/<slug>` trees; `manifest.json` lists each seeded defect's location and mechanism and lives outside any path the reviewer receives. `eval_recall.py --manifest` runs `review request` for each lane the requested number of times on a copy in a temp dir, matches findings to defects (location and mechanism both, one detection per defect, unrelated valid findings are not false positives) and prints strict recall and clean-control false positives per lane. The first value is a baseline, not a pass mark; one project with interlocking defects makes regressions a directional signal only.

## Design rationale

**Conversion route (D1 vs B2).** Measured on three papers (2608.18300, 2512.04388, 2503.17523) in the plan session on 2026-09-05: TeX → pandoc lost every table body (10/10 empty) and every `\cite`; `--citeproc` hung over two minutes on 21 bib entries. arXiv HTML (LaTeXML) → DOM cleanup → pandoc kept 14/14 tables with all cells, 84/84 references, and 429/429 equations via MathML `annotation` TeX. PDF → anydoc kept text and tables but lost most math and all figures, so it is the last resort with `known_losses: [math, figures]`.

**MathML stays in the DOM.** Replacing MathML with `$..$` text makes pandoc's HTML reader escape it (`\$\pi\_{\theta}\$`); leaving MathML and using writer `gfm-raw_html-tex_math_gfm+tex_math_dollars` yields `$\pi_{\theta}$`. Display equations sit in `table.ltx_equation`, which pandoc would emit as a table, so the adapter unwraps them to `<p>`.

**Figures.** `<object data=*.svg>` in LaTeXML output is the author's PDF figure rasterised to SVG (26 of 28 in 2503.17523). ImageMagick's built-in SVG renderer smears bar charts black (measured), so the adapter instead pulls the original PDF from the e-print tarball and renders it with `pdftoppm -png -r 110`, which is exact. `<svg><foreignObject>` blocks are tcolorbox text, not figures; their inner HTML is kept.

**Counts are not completeness (codex).** Structural counts only detect smoke; ordered content coverage catches truncation. Footnotes, listing lines and theorem/proof pairs lose their boundaries if spans are unwrapped blindly, so each has an explicit rule; everything else falls to "unwrap so the text survives, and let the check catch it."

**Alt-text in the alt slot only (B5).** Claude reads the Markdown and does not open each PNG, so a figure without text is a figure that does not exist. The alt slot is grammatically separate from caption and body, and the coverage check ignores it, so generated text cannot mask a lost block. It was off by default for cost; 성진 turned it on by default on 2026-09-06 because every saved paper now also gets a note, and the note agent reads figures through the alt text.

**Filenames are arXiv ids.** Author-year stems collide, get renamed, and break links (codex); the title lives in frontmatter and the index. Legacy ids replace `/` with `_`.

**Tests at repo root, per component.** Tests inside the skill directory would mix with skill loading and audits; `tests/<component>/` scales as more skills and agents arrive.

**The note is a pipeline step, not an orchestration (2026-09-06).** The invariant "every source gets a note" lived in `SKILL.md` prose, and every batch session re-performed it by hand: poll the jsonl, launch agents in waves, copy `conversion.check.missing` into each delegation, run `index` at the end. None of those steps needed a human judgment, and the facts they relayed were already data in the frontmatter. Under "if editing the tool would make the sentence false, the sentence belongs in the tool", the whole section moved into `save_paper.py`. Measured before building: `claude -p` runs nested inside a Claude Code Bash tool (`CLAUDECODE` set); `--agent paper-note` loads the project agent file as the system prompt with its model pin and tool list. The codex review of the plan (gpt-6-astra, read-only) added the staging path, the failure taxonomy, and the README-in-main-thread rule.

**Critical honesty in interfaces, not prose (B7 over more CLAUDE.md).** Harness-IF's measurement (rules against the default disposition are the least followed) plus one line from the codex design review — "if the review is merely callable, Claude can nod through every interface" — decided that the review is a precondition bound to an artefact hash rather than a step the skill asks for. The alternatives were a longer honesty section in CLAUDE.md (advisory, and the class of rule the paper measured as weakest) and a hook that blocks `build` without a review (a hook fires after the decision; a hash comparison inside the tool is re-read every call).

**Deny rules instead of a hook (B11 over D9).** The write path that matters is a subprocess, which neither a hook's command scan nor the deny rule can see; so the mechanical layer only has to stop mistakes, and the deny does that with no process spawn per Bash call and no over-firing substring scan. Provenance is the seal hash plus `run.json`'s git sha and dirty-diff hash (D14 declined as too heavy for one person).

**One skill, three rules, no references (B6/B9).** `research` triggers on one job 성진 names as one ("연구하자"), and the phase material branches on which file is open, not on which step of the skill is running, so a `paths:` rule loads without a routing decision where a `references/` file would need one. Root CLAUDE.md holds only what a long session cannot lose after compaction.

**One agent file owns the critic prompt (B10, same shape as D7).** Two independence axes: codex is a different model family; the claude lane does not share this conversation's framing. Both runners read the one body, so the prompt cannot fork. `model: opus` is pinned because the value of a review is the defect it did not miss; the cost is bounded by how often a review is requested (twice per project by the gates).

**Per-finding dispositions over concession scores (D13).** The scorer would be Claude; a numeric bar can be gamed in either direction and a rising bar punishes being right repeatedly. A disposition names what was done and who decided, and `human` is the honest exit when Claude and 성진 disagree.

**Structured divergence over open debate (D17).** AutoResearchClaw and ARS both needed a separate "do not flatten disagreement" rule, which is evidence the default flattens; `ideate` fixes the three conditions instead — different evidence per lane, an independent first round, and an ending that is a discriminating experiment or 성진's choice — and preserves the disagreements in the file.

**Numbers only through macros (B7 `paper verify`).** AutoResearchClaw's registry refuses unregistered numbers; going one step further and letting a number appear only as `\result{entry}{stat}{digits}` makes the registry the single source and the LaTeX build the enforcement, with `\nonresult{lit}{reason}` as the explicit exception so literature numbers stay citable.

**Templates are not bundled.** Guessing a style file's year is the trap scientific-agent-skills names; every project verifies the current file with `ultra-search` and `paper init --template` records source URL and hash.
