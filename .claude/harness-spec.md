# Harness Spec — Claude Researcher

## Context

Single-developer project (성진). The repo is the future home of a "veteran researcher assistant" harness: Claude discusses AI research and paper writing with 성진 through `AskUserQuestion`. The first component is `save-paper`, which fills the knowledge base under `papers/`.

Language: Python 3.12 scripts (bs4, lxml, requests, yaml already installed; no new dependencies), plus brew tools pandoc 3.10 and poppler, plus `npx @firecrawl/anydoc` for the PDF fallback. Tests: pytest under `tests/<component>/` at the repo root. No `pyproject.toml`. Harness prose is written in English (성진's decision); the Korean note output is in Korean. 성진 uses Claude Code vocabulary fluently, so the interview can name layers directly.

Distribution: this repo only. Not packaged as a plugin — the skill depends on brew tools and on the `papers/` path, so it would not travel anyway. (Assumed in the plan session, not explicitly confirmed by 성진.)

`AGENTS.md` is a symlink to `CLAUDE.md`, so both agents read one file.

## Goals

Save one arXiv paper as (1) a faithful, completeness-checked Markdown source under `papers/sources/<id>.md` with figures as PNG and provenance frontmatter, produced by a deterministic script, and (2) for papers 성진 chooses to study, a Korean restructured note under `papers/<id>.md` written by an opus subagent. Interpretation, summary, and cross-paper synthesis are out of scope here and belong to the research harness proper.

Quality bar for the source layer, in 성진's words: **strict on completeness, loose on formatting.** Paragraphs, table cells, equations, figures and references must all be present (machine-checked); line breaks, escape residue and empty table headers are left alone, because the reader of the source layer is an LLM.

## Component specs

### B1 `save-paper` skill

Readers: the Claude running the skill and 성진. Body target 60–90 lines, English. Sections: why two layers exist; Run (one command, `--help` is the source of truth for flags and exit codes); What the result means (exit 6 = saved but unverified, `route: pdf` = no math or figures, how to read `verified`); Decisions that are the user's (ambiguous title search, overwriting on a new version, turning on `--describe`, making a note); Korean note (what to hand `paper-note`, then `note-check` and `index`); Traps (project-specific only). No flag table, no install instructions (`doctor` says them), no architecture.

`allowed-tools: Bash(python3 .claude/skills/save-paper/scripts/save_paper.py *)` — one pre-approval, matched on the literal command text, so the skill body tells Claude to run exactly that relative form from the project root. The plan's `${CLAUDE_PROJECT_DIR}` form was dropped: that variable is empty inside the Bash tool, so the pattern could never match a working command. The script downloads only from `https://arxiv.org/`, writes only under `papers/`, and publishes atomically, so the prompt buys nothing and would fire once per paper in a batch. Treated as approved with the plan.

### B2 `save_paper.py` CLI and `savepaper/` package

Subcommands: `save`, `batch`, `describe`, `resolve`, `check`, `index`, `note-check`, `doctor`. Every argument carries `help=`; closed spaces use `choices=`. Exit codes: 0 ok / 2 usage / 3 resolve failed or ambiguous / 4 fetch failed / 5 convert failed / 6 saved but coverage check failed / 7 doctor or describe prerequisites missing.

Pipeline: resolve (URL, id, legacy id, or title → one exact `vN` and metadata from `export.arxiv.org/api/query`) → fetch into a staging directory (HTML at `arxiv.org/html/<id>v<n>`, e-print tarball for figure originals, PDF only on the `pdf` route) → LaTeXML DOM adapter (bs4) → pandoc `-f html -t gfm-raw_html-tex_math_gfm+tex_math_dollars` → coverage check against the original DOM → optional describe → frontmatter → atomic rename into `papers/sources/` → regenerate `papers/README.md`.

Modules: `arxiv.py` (ref parsing, Atom parsing, version pinning, 3 s process-wide rate limit honouring `Retry-After`, fetch), `latexml.py` (DOM adapter), `assets.py` (safe tarball extraction, `pdftoppm -png -r 110`, PNG/JPG copy, SVG fallback), `pandoc.py`, `pdfroute.py` (anydoc), `describe.py` + `describe_prompt.md`, `check.py`, `frontmatter.py`, `index.py`, `publish.py`, plus `errors.py` (exceptions carrying the exit codes), `pipeline.py` (the `save` transaction) and `notecheck.py` (`note-check`), added during implementation because the CLI file would otherwise hold the orchestration.

Security: tarball members with path escape or symlinks are refused; 50 MB per file and 500 MB total caps (`# 성진:` comment marks the limit); figure types confirmed by magic bytes; download URLs must start with `https://arxiv.org/`.

Coverage check: ordered content blocks from the untouched DOM (every `.ltx_p`, table cell, caption, `.ltx_bibitem`, footnote body, `ltx_listingline`, math annotation TeX) are normalised and looked up as substrings in the normalised Markdown. Any missing paragraph, caption, bibitem or table cell fails; unparsed math is a warning. Failure still saves the file, without `verified`, with `conversion.coverage` and `known_losses`, exit 6. The check guarantees fidelity to the HTML received, not that the HTML is the whole paper; the tarball `\bibitem` count is compared as a warning.

### B3 `paper-note` agent

`name: paper-note`, `tools: Read, Write, Bash`, `model: opus` — pinned because long-form Korean rewriting fidelity is the whole value; one run per saved paper, launched in parallel when several papers are saved together. No `memory`. The body is a full system prompt: restructure, never summarise; substance 100 %, scaffolding dropped; numbers, equations and tables verbatim; author-acknowledged limits and note-writer-observed boundaries in separate sections; figures read from the PNGs with `Read`, embedded as `![](sources/images/...)`; reference list not copied, in-text citations kept author-year; 평어체; Markdown limited to headings, bold, code, images, tables. Output: frontmatter (`type: Paper Note`, `sources`, `generated`, `status: draft`, `tags`, `related`) then `# 🖇️<Korean title>`. Ends by running `save_paper.py note-check` and reporting its output verbatim. Undecided points are returned as results, since `AskUserQuestion` does not exist in a subagent.

### B4 `CLAUDE.md`

About five lines: what the two layers under `papers/` are and which to read when, that `papers/README.md` is generated and never hand-edited, and that saving a paper goes through `/save-paper`. No inventory.

### B5 `describe.py`

OpenRouter chat completions, model `openai/gpt-5.6-luna`, `reasoning.effort: high`, `max_tokens: 16000`, `provider: { require_parameters: true, sort: price }`, JSON-schema response `{description}` — values measured in 성진's `generate_description.js`. Key `OPENROUTER_API_KEY` and optional model `OPENROUTER_MODEL` from the environment, then `scripts/savepaper/.env` beside the code (성진's preference; `.env.example` committed there), then a project-root `.env`. Without a key `save` warns and leaves the alts empty; only `describe <id>` exits 7. Prompt in `describe_prompt.md` next to the code, adapted from 성진's `prompt_description.md`. Writes the alt slot of `![alt](path)` only; failed images keep an empty alt and are counted in `figures_described.failed`. On by default in `save` and `batch` (`--no-describe` opts out) since 2026-09-06.

## Design rationale

**Conversion route (D1 vs B2).** Measured on three papers (2608.18300, 2512.04388, 2503.17523) in the plan session on 2026-09-05: TeX → pandoc lost every table body (10/10 empty) and every `\cite`; `--citeproc` hung over two minutes on 21 bib entries. arXiv HTML (LaTeXML) → DOM cleanup → pandoc kept 14/14 tables with all cells, 84/84 references, and 429/429 equations via MathML `annotation` TeX. PDF → anydoc kept text and tables but lost most math and all figures, so it is the last resort with `known_losses: [math, figures]`.

**MathML stays in the DOM.** Replacing MathML with `$..$` text makes pandoc's HTML reader escape it (`\$\pi\_{\theta}\$`); leaving MathML and using writer `gfm-raw_html-tex_math_gfm+tex_math_dollars` yields `$\pi_{\theta}$`. Display equations sit in `table.ltx_equation`, which pandoc would emit as a table, so the adapter unwraps them to `<p>`.

**Figures.** `<object data=*.svg>` in LaTeXML output is the author's PDF figure rasterised to SVG (26 of 28 in 2503.17523). ImageMagick's built-in SVG renderer smears bar charts black (measured), so the adapter instead pulls the original PDF from the e-print tarball and renders it with `pdftoppm -png -r 110`, which is exact. `<svg><foreignObject>` blocks are tcolorbox text, not figures; their inner HTML is kept.

**Counts are not completeness (codex).** Structural counts only detect smoke; ordered content coverage catches truncation. Footnotes, listing lines and theorem/proof pairs lose their boundaries if spans are unwrapped blindly, so each has an explicit rule; everything else falls to "unwrap so the text survives, and let the check catch it."

**Alt-text in the alt slot only (B5).** Claude reads the Markdown and does not open each PNG, so a figure without text is a figure that does not exist. The alt slot is grammatically separate from caption and body, and the coverage check ignores it, so generated text cannot mask a lost block. It was off by default for cost; 성진 turned it on by default on 2026-09-06 because every saved paper now also gets a note, and the note agent reads figures through the alt text.

**Filenames are arXiv ids.** Author-year stems collide, get renamed, and break links (codex); the title lives in frontmatter and the index. Legacy ids replace `/` with `_`.

**Tests at repo root, per component.** Tests inside the skill directory would mix with skill loading and audits; `tests/<component>/` scales as more skills and agents arrive.
