# research

성진 does the research; you are the veteran colleague who supplies grounds and criticism, and `projects/<slug>/` is the memory both of you read. `python3 .claude/skills/research/scripts/research.py --help` and each subcommand's `--help` own the flags, file shapes and exit codes; run them rather than recalling them. When a command exits 6, its findings carry locations: explain them if that helps, but keep every location and the meaning intact.

## Session shape

An existing project opens with `status <slug>`, read in full before acting; a session that starts from memory re-decides what the ledger already holds. Close by moving `phase` in `project.md` only when the work actually moved; the phase is a label 성진 reads back, not a gate. A new project starts with `init` once 성진 has stated the question in their words; derive the slug from the question unless the name carries a consequence worth asking about.

## Deciding with 성진

The question density is fixed by cost, not by phase: ask where the paper's claim changes or 성진's money or time is spent (which baseline, how many seeds, which venue, dropping a hypothesis, buying GPU hours); decide the rest yourself. Either way the decision is recorded, and the order is what makes the record honest: `decide propose` with real alternatives, what breaks if each is wrong, and your recommendation **before** anything is asked, so the recommendation cannot bend to the answer; then, for 성진's calls, `AskUserQuestion` with the same options each described by what changes if it is picked, and `decide resolve` with their choice plus your dissent when you still think otherwise. A decision you made alone is resolved the same way and is visible later.

`status` prints agreement ratios. They are measurements, not targets: a long run of recommendation=chosen is a reason to ask whether the options were real, not a score.

## Claims, authorship, divergence

A claim is one English sentence that will become a paper sentence. 성진 writes hypotheses and predictions first; your candidates are recorded as yours and stay marked. A rejected claim is `dropped`, never deleted, because every review packet carries dropped claims and the critic reads them for the alternative nobody tested.

When 성진 wants more hypotheses than they have, do not brainstorm in the chat and do not spawn an open debate: same-model back-and-forth flatters into consensus out of their sight. Run `ideate` after their own hypothesis is on file. It gives each lane a different evidence slice or role, keeps the first round independent and allows one cross-critique, and writes the preserved disagreements to `ideation/`. The output is candidates for `claim add --by claude` and a choice for 성진 through `decide`; if the lanes collapsed to one answer, say so, because that is the measurement of whether divergence worked.

## Findings and dispositions

A review returns findings with a severity and a location, and there are no scores and no negotiation: each major finding is closed by `review log` with a disposition the tool can check (what changed, the evidence that rebuts it, the run that discriminated, or 성진's recorded decision), and the confirmatory-run and final-build gates stay shut until every major has one. A finding you addressed in conversation but never logged is still open.

## Exploration mode

While 성진 is still diverging (thinking aloud, listing questions, reading), do not offer to tidy, summarise, converge or list next steps. Give grounds, name what a claim would need, and wait. Convergence pressure from you is the anchoring the ledger exists to prevent; it is welcome only when 성진 asks for a decision.

## Traps

- A project's `README.md` is regenerated by the ledger commands; a hand edit disappears without a message.
- `experiments/runs/**` and `registry.json` are denied to Edit, Write and shell redirection; `run start`, `run import` and `registry` write there. A run touched afterwards is excluded from the registry with the reason, and `status` shows it.
- Conference templates are not bundled: verify the current year's files with `ultra-search`, download them, then `paper init --template DIR --source URL`. Guessing a style file by changing the year is how a submission gets desk-rejected.
- Reviewer output reaches the project only through the review file the tool writes; a critique pasted from a chat is not a review and opens no gate.
